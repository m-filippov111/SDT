**Занятие 3.1. Архитектура приложения и организация кода**

1\. Назначение

Сформировать у обучающихся понимание принципов построения архитектуры серверных приложений на Python, навыков организации кода в пакеты и модули, управления зависимостями и работы с виртуальными окружениями. Занятие закладывает основу для разработки серверной части командного проекта.

2\. Проверяемые результаты обучения

| Код | Индикатор | Уровень | Дескриптор освоения |
| --- | --- | --- | --- |
| PL-1.1 | Разрабатывает и отлаживает прикладные решения разной сложности с использованием Python, тестирует, испытывает и оценивает их качество | С   | Обучающийся способен проектировать структуру приложения, выделять слои и компоненты, организовывать код в пакеты и модули, управлять зависимостями и настраивать виртуальные окружения для изоляции проектов |

3\. Условия выполнения

| Параметр | Значение |
| --- | --- |
| Форма контроля | Текущая (практическая работа) |
| Время выполнения | 4 академических часа (2 часа — лекция с разбором, 2 часа — практическая работа) |
| Формат сдачи | Git-репозиторий команды (обновлённая структура проекта) |
| Режим выполнения | Индивидуально-групповой (лекция — общая, практика — в командах) |
| Используемые инструменты | Python 3.10+, pip, venv/poetry, Git, IDE (PyCharm/VSCode) |
| Допустимые источники | Документация Python, материалов лекций, официальная документация poetry |
| Правила использования ИИ | Разрешено для объяснения концепций и помощи в настройке. Документируется в ai-usage-log.md |

4\. Задание. Практическая работа (2 часа)

Задание выполняется на данных и предметной области командного проекта. Подсистема обработки данных должна стать частью работающего приложения, а не отдельным скриптом «в стол».

Этап 1. Реализация базового FastAPI приложения

Создайте файл src/main.py:

python

"""

Точка входа в приложение.

"""

from fastapi import FastAPI

from src.api.routes import health

app = FastAPI(

title="Командный проект",

version="0.1.0",

description="Серверная часть командного проекта"

)

_\# Подключение роутеров_

app.include_router(health.router)

if \__name__ == "\__main_\_":

import uvicorn

uvicorn.run(

"src.main:app",

host="0.0.0.0",

port=8000,

reload=True

)

Создайте файл src/api/schemas/health.py:

python

"""

Pydantic схемы для health-check.

"""

from pydantic import BaseModel

class HealthResponse(BaseModel):

"""Ответ health-check."""

status: str

version: str

environment: str

Создайте файл src/api/routes/health.py:

python

"""

Маршруты для health-check.

"""

from fastapi import APIRouter

from src.api.schemas.health import HealthResponse

router = APIRouter(prefix="/health", tags=\["health"\])

@router.get("/", response_model=HealthResponse)

async def health_check() -> HealthResponse:

"""

Проверка работоспособности приложения.

"""

return HealthResponse(

status="ok",

version="0.1.0",

environment="development"

)

Этап 4. Настройка тестов

Создайте файл tests/test_health.py:

python

"""

Тесты для health-check.

"""

import pytest

from fastapi.testclient import TestClient

from src.main import app

client = TestClient(app)

def test_health_check():

"""Тест маршрута /health."""

response = client.get("/health/")

assert response.status_code == 200

data = response.json()

assert data\["status"\] == "ok"

assert data\["version"\] == "0.1.0"

Добавьте pytest в requirements.txt:

txt

pytest==7.4.3

httpx==0.25.1 # для TestClient

8\. Методические рекомендации

Для студентов

1.  Начинайте с простого — сначала добейтесь работающего health-check, потом усложняйте структуру
2.  Используйте IDE — PyCharm и VSCode имеют встроенную поддержку Python и упрощают навигацию по пакетам
3.  Не забывайте про \__init_\_.py — даже пустые файлы необходимы для правильного импорта
4.  Активность виртуального окружения — проверяйте, что вы находитесь в окружении (which python показывает путь к .venv)
5.  Документируйте решения — архитектура и организация кода должны быть понятны всем участникам команды

Для преподавателей

1.  Проверьте, что все студенты корректно настроили виртуальное окружение и добавили его в .gitignore
2.  Убедитесь, что структура проекта соответствует принципам слоистой архитектуры
3.  Оцените качество документации в docs/architecture.md — она должна отражать понимание принципов организации кода
4.  Проверьте, что health-check работает локально у каждого участника команды
