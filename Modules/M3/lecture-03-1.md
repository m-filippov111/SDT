Сформировать у обучающихся понимание принципов построения архитектуры серверных приложений на Python, навыков организации кода в пакеты и модули, управления зависимостями и работы с виртуальными окружениями. Занятие закладывает основу для разработки серверной части командного проекта.

## 3. Архитектура приложения: слои и компоненты

Архитектура приложения — это фундаментальная организация системы, определяющая её компоненты, их взаимосвязи и принципы взаимодействия. Для серверных приложений на Python наиболее распространена многослойная архитектура:

+-----------------------------------------------------------------------+

### Ключевые принципы организации слоёв

| Принцип | Описание |
|---------|----------|
| **Разделение ответственности** | Каждый слой отвечает за свою область: презентация — за взаимодействие с пользователем, бизнес-логика — за правила предметной области, инфраструктура — за внешние системы |
| **Зависимости внутрь** | Внешние слои зависят от внутренних, но не наоборот. Presentation → Application ← Infrastructure (инверсия зависимостей) |
| **Слабые связи** | Слои взаимодействуют через чёткие интерфейсы, что упрощает тестирование и замену компонентов |
| **Тестируемость** | Каждый слой можно тестировать изолированно (модульные тесты для бизнес-логики, интеграционные — для инфраструктуры) |

## 4. Пакеты и модули в Python

**Модуль** — это файл с расширением `.py`, содержащий определения функций, классов и переменных.

**Пакет** — это директория, содержащая файл `__init__.py` (может быть пустым) и другие модули/пакеты.

## 5. Управление зависимостями

**Зависимость** — это внешний пакет/библиотека, необходимый для работы вашего приложения.

### Основные подходы к управлению зависимостями в Python

| Инструмент | Назначение | Особенности |
|------------|------------|-------------|
| `pip` + `requirements.txt` | Базовое управление | Простой, но требует ручного обновления версий |
| `poetry` | Современный менеджер | Автоматическое разрешение зависимостей, версионирование, публикация |
| `pipenv` | Альтернатива poetry | Объединяет pip и virtualenv |
| `conda` | Для научных вычислений | Управляет не только Python, но и системными библиотеками |
