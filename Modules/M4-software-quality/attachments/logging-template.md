# Соглашение по структурированному логированию

> Заполняется командой (КИМ-4.1, этап 5).

## 1. Цели

Зачем логи в проекте: [диагностика ошибок API / аудит операций / …].

## 2. Технические правила

| Параметр | Значение |
| --- | --- |
| Библиотека | `logging` (стандартная) / [иное] |
| Формат записи | [время, уровень, модуль, request_id, сообщение] |
| Куда пишем | [stdout / файл `logs/app.log`] |
| Уровень по умолчанию | [INFO] |
| Уровень в разработке | [DEBUG] |

Пример формата:

```text
2026-03-15 12:01:03,441 | INFO | api.grades | req=9f3a… | grade created student_id=42
```

## 3. Что логируем

| Событие | Уровень | Обязательные поля контекста |
| --- | --- | --- |
| Вход в ключевой endpoint | INFO | `request_id`, имя операции |
| Успешное завершение | INFO | `request_id`, идентификатор сущности |
| Ошибка валидации | WARNING | `request_id`, код ошибки |
| Неожиданное исключение | ERROR | `request_id`, тип исключения (без секретов) |

## 4. Что нельзя писать в лог

- пароли, токены, ключи API;
- полные персональные данные без необходимости;
- тела запросов целиком, если в них могут быть секреты.
