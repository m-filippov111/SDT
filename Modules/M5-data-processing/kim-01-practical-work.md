# КИМ-5.1. Подсистема обработки данных приложения

## 1. Назначение

Проверить сформированность индикаторов **PL-1.2** и **PL-1.3** (уровень Б): способность обоснованно выбрать библиотеки обработки и визуализации данных под сформулированные требования и реализовать простой конвейер обработки данных (ETL) с обработкой ошибок, интегрированный в серверное приложение командного проекта.

## 2. Проверяемые результаты обучения

| Код | Индикатор | Уровень | Дескриптор освоения |
| --- | --- | :---: | --- |
| PL-1.2 | Осуществляет выбор инструментов разработки на Python для создания прикладной системы обработки данных с заданными требованиями | Б | Обучающийся способен сформулировать требования к обработке данных, сопоставить библиотеки (NumPy, Pandas, Matplotlib и др.) по критериям и обосновать выбор под задачу проекта |
| PL-1.3 | Разрабатывает и поддерживает системы обработки больших данных различной степени сложности | Б | Обучающийся способен реализовать ETL-конвейер (извлечение, преобразование, загрузка) с обработкой ошибок и логированием и интегрировать его в приложение |

**Данные для работы.** Задание выполняется на данных предметной области вашего проекта. Если реальных данных ещё нет, возьмите открытый набор данных, близкий к теме, — например, с [Kaggle Datasets](https://www.kaggle.com/datasets). Для тренировки на классическом наборе подойдёт [Titanic Dataset](https://www.kaggle.com/c/titanic/data) (табличный CSV с пропусками в ряде колонок — удобен для отработки очистки, обработки некорректных данных, агрегации и визуализации). Ссылку на использованный датасет, его формат и объём укажите в `docs/data-requirements.md`.

## 4. Задание

Задание выполняется на данных и предметной области командного проекта. Подсистема обработки данных должна стать частью работающего приложения, а не отдельным скриптом «в стол».

### Этап 1. Требования к обработке данных

В файле `docs/data-requirements.md` опишите:

- какие данные поступают на вход подсистемы (источник, формат, объём);
- какие преобразования нужны (очистка, агрегация, объединение, расчёт показателей);
- что является результатом (таблица, отчётная выборка, визуализация) и кто его потребитель;
- нефункциональные требования: допустимое время обработки, поведение при некорректных данных.

### Этап 2. Обоснование выбора библиотек (PL-1.2)

Сопоставьте библиотеки обработки и визуализации данных под сформулированные требования и обоснуйте выбор в файле `docs/library-choice.md`:

1. Приведите **критерии выбора** (пригодность под тип данных и объём, производительность, читаемость кода, интеграция с приложением, зрелость и поддержка).
2. Сравните минимум **две альтернативы** по каждому ключевому критерию (например, Pandas против чистого Python/`csv`; Matplotlib против альтернативной библиотеки визуализации).
3. Сделайте вывод: какие библиотеки выбраны и почему именно они подходят под требования проекта.

### Этап 3. ETL-конвейер (PL-1.3)

Реализуйте конвейер обработки данных в модуле `src/pipeline/`:

- **Extract** — извлечение данных из источника (файл, внешний API или таблица СУБД).
- **Transform** — преобразования средствами Pandas/NumPy согласно требованиям этапа 1.
- **Load** — загрузка результата в хранилище проекта (таблица СУБД или отчётный файл).

Требования к конвейеру:

- **обработка ошибок** — некорректные или отсутствующие данные не должны «ронять» весь конвейер; предусмотрите обработку исключений и понятные сообщения;
- **логирование** — ключевые шаги и ошибки пишутся в лог (модуль `logging`);
- **идемпотентность** — повторный запуск на тех же входных данных не создаёт дублей.

### Этап 4. Воспроизводимый запуск

Обеспечьте запуск конвейера по документированному регламенту:

- конвейер запускается одной командой (`python -m src.pipeline`) и отрабатывает без ручного вмешательства в промежуточные шаги;
- в `docs/data-pipeline.md` опишите регламент: как запустить, где взять входные данные, где смотреть логи и результат, что делать при сбое.

### Этап 5. Отчётная выборка и визуализация

1. Постройте отчётную выборку (агрегированный показатель предметной области проекта).
2. Средствами Matplotlib постройте **минимум одну** осмысленную визуализацию результата; сохраните её и/или отдавайте через приложение.

### Этап 6. Интеграция с приложением

Подключите подсистему данных к серверной части (модуль 3):

- добавьте endpoint FastAPI, возвращающий отчётную выборку или визуализацию (например, `GET /reports/...`);
- результат конвейера доступен пользователю через API, а не только в виде локального файла.

### Этап 7. Тесты подсистемы данных

Покройте `pytest`-тестами ключевую логику преобразований:

- минимум по одному тесту на корректные данные, на граничный случай и на некорректные данные (проверка обработки ошибок).

### Чеклист приёмки

Работа принимается, когда выполнены все пункты. Это же список проверяет преподаватель.

- [ ] В `docs/data-requirements.md` описаны вход, преобразования, результат и поведение при некорректных данных.
- [ ] В `docs/library-choice.md` заданы критерии выбора и сравнены минимум две альтернативы; сделан обоснованный вывод.
- [ ] Конвейер `src/pipeline/` разделён на шаги extract / transform / load.
- [ ] Конвейер запускается одной командой `python -m src.pipeline` и отрабатывает без ручного вмешательства.
- [ ] На входе с пропусками или неверными типами конвейер не падает: ошибочные строки логируются и пропускаются.
- [ ] Ключевые шаги и ошибки пишутся в лог.
- [ ] Повторный запуск на тех же данных не создаёт дублей.
- [ ] Построена отчётная выборка и хотя бы одна визуализация средствами Matplotlib.
- [ ] Результат доступен через endpoint FastAPI (например, `GET /reports/...`).
- [ ] Есть тесты на корректные, граничные и некорректные данные (`tests/test_pipeline.py`).
- [ ] Файлы размещены по структуре из раздела «Формат сдачи».

## 6. Критерии оценивания

Баллы за критерий выставляются по чеклисту приёмки: полностью закрытые пункты критерия — верхняя граница веса, частично — середина, не закрыты — ноль.

| № | Критерий | Вес | Проверяемые пункты чеклиста |
| --- | --- | :---: | --- |
| 1 | Требования к обработке данных | 10% | Вход, преобразования, результат и поведение при некорректных данных описаны |
| 2 | Обоснование выбора библиотек (PL-1.2) | 20% | Критерии заданы, сравнены две альтернативы, вывод обоснован |
| 3 | ETL-конвейер (PL-1.3) | 25% | Шаги extract/transform/load разделены, преобразования соответствуют требованиям |
| 4 | Обработка ошибок и воспроизводимость | 15% | Ошибки логируются и не роняют конвейер, есть идемпотентность, запуск одной командой |
| 5 | Отчётная выборка и визуализация | 15% | Построена выборка и корректная визуализация Matplotlib |
| 6 | Интеграция с приложением | 10% | Результат доступен через endpoint FastAPI |
| 7 | Тесты подсистемы данных | 5% | Есть тесты на корректные, граничные и некорректные данные |

Оформление репозитория (структура, читаемость документации) учитывается в пределах критериев 1–7.

## 8. Методические рекомендации

### Для студентов

1. **Выбор библиотек** оценивается по обоснованию, а не по названию: покажите, почему выбранный инструмент подходит под ваши данные и объём.
2. **Обработка ошибок** — сознательно проверьте поведение конвейера на «грязных» данных (пропуски, неверные типы, пустой вход).
3. **Воспроизводимость важнее автоматизации**: конвейер должен запускаться одной понятной командой и давать одинаковый результат на одних и тех же данных.
4. **Интеграция важнее объёма**: небольшой, но встроенный в приложение конвейер ценнее большого автономного скрипта.

### Для преподавателей

1. Проверяйте работу по чеклисту приёмки — он же список демонстрации на спринт-ревью.
2. Запросите демонстрацию поведения конвейера на некорректных данных.
3. Убедитесь, что результат доступен через API, а не только как локальный файл.
4. Задавайте вопросы автору кода конвейера индивидуально (по истории репозитория).

## 9. Пример выполнения

> **Проект**: «Система мониторинга успеваемости студентов».
>
> **Требование к данным**: подгружать выгрузку оценок (CSV), считать средний балл и динамику по каждой дисциплине, отдавать отчёт преподавателю.
>
> **Выбор библиотек**: Pandas — табличные преобразования и агрегация (удобные группировки, работа с пропусками); Matplotlib — график динамики среднего балла. Альтернатива (чистый `csv` + ручные циклы) отклонена: хуже читаемость и обработка пропусков.
>
> **Конвейер**: `extract` читает CSV и валидирует колонки → `transform` чистит пропуски, считает средние и динамику → `load` пишет агрегаты в таблицу `reports`. Ошибки формата логируются, строка пропускается, конвейер продолжает работу.
>
> **Запуск**: одной командой `python -m src.pipeline`; логи — в `logs/pipeline.log`, результат — в таблице `reports`.
>
> **API**: `GET /reports/discipline/{id}` возвращает агрегаты и ссылку на график.
