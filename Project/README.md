# Модуль 6. Командный программный проект (сквозной)

## Описание модуля

Модуль 6 — интегральная проектная работа: команды по 3–5 человек в течение семестра разрабатывают работающий программный продукт, проходя полный цикл — от формализации требований и планирования до тестирования, обработки данных, интеграции и публичной защиты. Проект выполняется **сквозным образом параллельно модулям 2–5** и структурирован спринтами: содержание каждого модуля сразу применяется к очередной работающей части продукта.

Проектная работа — интегральный КИМ, проверяющий несколько компетенций и индикаторов в условиях комплексной практической задачи, поэтому она не дублирует отдельный модуль, а собирает их результаты воедино. Материалы модуля 6 размещены в каталоге `Project/`, а не в `Modules/`, именно потому, что это сквозной интегральный КИМ, а не последовательный модуль.

## Требования к проекту

Тема выбирается командой на модуле 1 и должна допускать реализацию за семестр. Обязательные элементы решения:

- **серверная часть на Python (FastAPI)** — REST API, слои приложения, работа с БД через ORM;
- **хранилище данных** — реляционная СУБД, подключённая через ORM с миграциями схемы;
- **подсистема обработки данных** — ETL-конвейер и отчётная выборка (модуль 5);
- **инженерная обвязка** — репозиторий с ветвлением, код-ревью, автоматические проверки (модуль 2).

## Спринты и их связь с модулями

Проект синхронизирован с модулями: каждый спринт даёт готовую, работающую часть продукта, которую команда показывает на очередном спринт-ревью.

| Спринт | Опорный модуль | Что готово к концу спринта | Спринт-ревью |
| --- | --- | --- | :---: |
| 1 | Модуль 3 | Серверная часть: API, модели данных, подключение хранилища | 6.2 |
| 2 | Модуль 4 | Качество: тесты ключевой логики, CI, взаимное код-ревью | 6.3 |
| 3 | Модуль 5 | Подсистема данных: ETL-конвейер и отчётная выборка | 6.4 |

## Как устроена оценка

Проект оценивается по трём контурам, накопительно в течение семестра (100 баллов): текущий контроль (артефакты репозитория и лабораторные модулей 2–5), рубежный (три спринт-ревью, 30 баллов) и промежуточная аттестация (защита, 40 баллов). Полная процедура, шкала и правила индивидуальной оценки — в [exam.md](../Exam/exam.md).

## Чеклист готовности к защите

Продукт готов к защите, когда выполнены все пункты:

- [ ] Приложение запускается по инструкции из README и доступно через API/интерфейс.
- [ ] Работает REST API (FastAPI) с несколькими endpoint'ами.
- [ ] Данные хранятся в реляционной СУБД через ORM; есть миграции схемы.
- [ ] Работает подсистема обработки данных: ETL-конвейер и отчётная выборка (модуль 5).
- [ ] Ключевая логика покрыта тестами, CI проходит успешно.
- [ ] В каждом спринте у каждого участника есть собственные pull request и участие в код-ревью.
- [ ] Актуальны матрица RACI, командные соглашения и `ai-usage-log.md`.
- [ ] Готовы три отчёта `sprint-N-review.md`.
- [ ] README проекта содержит назначение, схему архитектуры и инструкцию запуска.
