# КИМ-6.1. Спринт-ревью командного проекта

## 1. Назначение

Проверить сформированность индикаторов **SS-2.1** и **SS-2.2** (уровень Б) в рубежном контроле: способность организовать командную работу, распределить и выполнить зоны ответственности, ставить задачи людям и ИИ-агентам с критериями приёмки и представлять результат в понятном аудитории формате. Три спринт-ревью — контрольные точки, в которых вклад каждого участника фиксируется трижды за семестр, а не однократно на защите.

Работающая часть продукта, которую команда показывает на спринт-ревью, служит наблюдаемым свидетельством по индикаторам **PL-1.1, PL-1.2, PL-1.3**: соответствующая часть кода оценивается по рубрикам опорных модулей (3, 4, 5).

## 2. Проверяемые результаты обучения

| Код | Индикатор | Уровень | Дескриптор освоения |
| --- | --- | :---: | --- |
| SS-2.1 | Эффективно коммуницирует с участниками проектной команды, включая постановку задач людям и ИИ-агентам, фиксацию договорённостей и критериев качества | Б | Обучающийся способен вести бэклог с критериями приёмки, ставить задачи исполнителям (в том числе ИИ) и верифицировать результат, фиксировать командные соглашения и отчитываться о ходе спринта |
| SS-2.2 | Учитывает профессиональные и ролевые особенности коллег: распределяет ответственность (RACI) и представляет результаты в понятном формате | Б | Обучающийся способен принять и выполнить свою зону ответственности по матрице RACI и представить результат своей работы понятно заданной аудитории |

## 3. Условия выполнения

| Параметр | Значение |
| --- | --- |
| **Форма контроля** | Рубежная |
| **Количество точек** | Три спринт-ревью (по одному в конце каждого спринта) |
| **Формат сдачи** | Git-репозиторий команды + отчёт `sprint-N-review.md` + демонстрация на занятии |
| **Режим выполнения** | Групповой (3–5 человек); вклад оценивается индивидуально |
| **Используемые инструменты** | Git-репозиторий, задачный трекер, ИИ-ассистенты, работающее приложение проекта |
| **Правила использования ИИ** | Разрешено по командным соглашениям; применение ИИ и верификация результатов фиксируются в `ai-usage-log.md` |

## 4. Задание

Каждый спринт завершается спринт-ревью по единому регламенту. Всего за семестр — три ревью, синхронизированные с модулями.

| Спринт-ревью | После спринта | Что показывает команда |
| --- | --- | --- |
| 1 (занятие 6.2) | Спринт 1 (модуль 3) | Серверную часть: API, модели данных, подключение хранилища через ORM |
| 2 (занятие 6.3) | Спринт 2 (модуль 4) | Тесты ключевой логики, работающий CI, результаты взаимного код-ревью |
| 3 (занятие 6.4) | Спринт 3 (модуль 5) | Подсистему данных: ETL-конвейер, отчётную выборку и визуализацию |

### Регламент одного спринт-ревью

1. **Показ готовой части.** Команда показывает работающую часть продукта на подготовленных данных — запущенное решение, а не слайды.
2. **Отчёт о ходе спринта.** Что планировалось и что сделано; отклонения от бэклога и их причины.
3. **Распределение задач и вклад.** Кто над чем работал (матрица RACI и история репозитория); фиксация фактического вклада каждого участника.
4. **Работа с ИИ.** Где применялись ИИ-ассистенты и как верифицировались их результаты (по командным соглашениям).
5. **Анализ и корректировка.** Краткая ретроспектива: что улучшить; обновление бэклога следующего спринта.
6. **Индивидуальные ответы.** Каждый участник отвечает на вопросы по своим задачам.

### Отчёт `sprint-N-review.md`

По каждому спринт-ревью в репозитории готовится отчёт, включающий:

- цель спринта и запланированные задачи;
- что реализовано (со ссылками на pull request и задачи трекера);
- таблицу вклада участников (кто какие задачи закрыл);
- отметку о применении ИИ и верификации результатов;
- выводы ретроспективы и корректировку бэклога.

### Чеклист спринт-ревью

Спринт-ревью засчитывается, когда выполнены все пункты. Это же список проверяет преподаватель.

- [ ] Показана работающая часть продукта на подготовленных данных (запущенное решение, не слайды).
- [ ] Показанное соответствует опорному модулю спринта (см. таблицу выше).
- [ ] Отчёт `sprint-N-review.md` заполнен: цель, сделанное, вклад участников, работа с ИИ, выводы.
- [ ] Вклад каждого участника подтверждается его pull request'ами и задачами трекера.
- [ ] Матрица RACI актуальна на дату ревью.
- [ ] Применение ИИ отражено в `ai-usage-log.md`, результаты верифицированы.
- [ ] Проведена ретроспектива, бэклог следующего спринта обновлён.
- [ ] Каждый участник ответил на вопросы по своим задачам.

## 5. Формат сдачи

```text
team-XX-project/
├── docs/
│   ├── raci-matrix.md         # актуальная матрица ответственности
│   ├── ai-usage-log.md        # применение и верификация ИИ
│   ├── sprint-1-review.md     # отчёт по спринт-ревью 1
│   ├── sprint-2-review.md     # отчёт по спринт-ревью 2
│   └── sprint-3-review.md     # отчёт по спринт-ревью 3
└── (код работающей части соответствующего спринта)
```

## 6. Критерии оценивания

Критерии применяются к каждому из трёх спринт-ревью; итог рубежного контроля — среднее по трём точкам. Баллы за критерий выставляются по чеклисту: закрытые пункты — верхняя граница веса, частично — середина, не закрыты — ноль.

| № | Критерий | Вес | Проверяемые пункты чеклиста |
| --- | --- | :---: | --- |
| 1 | Показ готовой части продукта | 30% | Работающая часть показана и соответствует опорному модулю спринта |
| 2 | Соответствие цели спринта и бэклогу | 15% | Показанное отвечает запланированным задачам; отклонения объяснены |
| 3 | Распределение задач и фиксация вклада | 20% | Вклад участников подтверждён pull request'ами, задачами трекера и RACI |
| 4 | Работа с ИИ по соглашениям | 10% | Применение ИИ задокументировано в `ai-usage-log.md`, результаты верифицированы |
| 5 | Анализ спринта и корректировка бэклога | 10% | Проведена ретроспектива, бэклог следующего спринта обновлён |
| 6 | Индивидуальные ответы участников | 15% | Каждый участник ответил на вопросы по своим задачам |

## 7. Шкала оценивания

| Уровень | Диапазон баллов | Характеристика |
| --- | :---: | --- |
| Базовый | 60–79% | Работающая часть показана, вклад распределён, но часть пунктов чеклиста не закрыта (отчёт неполон или ретроспектива формальна) |
| Базовый + | 80–89% | Закрыты все ключевые пункты: рабочая часть продукта, зафиксированный вклад, документированная работа с ИИ |
| Базовый ++ | 90–100% | Закрыт весь чеклист: содержательный показ, прозрачный вклад, осмысленная ретроспектива |
| Ниже базового | < 60% | Показанное не работает или вклад участников не прослеживается |

## 8. Методические рекомендации

### Для студентов

1. Показывайте **работающую** часть продукта, а не описание планов.
2. Держите матрицу RACI и бэклог актуальными — по ним оценивается вклад.
3. Пропуск спринт-ревью отрабатывается в течение недели; повторный пропуск закрывает допуск к защите до отработки (см. [exam.md](../Exam/exam.md)).

### Для преподавателей

1. Сверяйте заявленный вклад с историей репозитория и задачами трекера.
2. Задавайте индивидуальные вопросы каждому участнику по его задачам.
3. Фиксируйте вклад в каждой из трёх точек — это основа индивидуальной оценки на защите.
