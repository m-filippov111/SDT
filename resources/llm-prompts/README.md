## Промпт-шаблоны

### 1. Генерация тестов (pytest)

**Назначение:** создание модульных тестов для Python-функций.

**Модель/сервис:** ChatGPT / Claude / YandexGPT

**Входные данные:**

- Код функции
- Краткое описание функциональности
- Список edge-cases

**Промпт:**

```text
Ты — эксперт по тестированию на Python. Напиши модульные тесты с использованием pytest для следующей функции:

[код функции]

Задача: [краткое описание что делает функция]

Требования к тестам:

Покрыть все основные сценарии использования

Покрыть все edge-cases (пустые входные данные, граничные значения, ошибки)

Использовать фикстуры для повторяющихся данных

Использовать parametrize для тестирования нескольких случаев

Добавить проверку типов (если есть аннотации)

Тесты должны быть самодокументируемыми (понятные названия)

Формат ответа: только код на Python с комментариями.
```

**Способ верификации:** запустить тесты, проверить покрытие, убедиться, что все edge-cases покрыты.

### 2. Рефакторинг кода

**Назначение:** улучшение качества существующего кода (упрощение, устранение дублирования, добавление аннотаций типов).

**Модель/сервис:** ChatGPT / Claude / GitHub Copilot

**Входные данные:**

- Исходный код
- Цели рефакторинга

**Промпт:**

```
Ты — эксперт по рефакторингу Python-кода. Проведи рефакторинг следующего кода:

[код]

Цели:
1. Уменьшить цикломатическую сложность (выделить вложенные условия в отдельные функции)
2. Устранить дублирование кода (DRY)
3. Добавить аннотации типов
4. Улучшить читаемость (понятные имена переменных, комментарии)
5. Выделить бизнес-логику в отдельные функции
6. Если возможно — использовать современные Python-конструкции

Формат ответа: обновлённый код + краткое описание изменений.
```

3. Написание документации (Google/NumPy формат)

**Назначение:** создание документации для функции или модуля.

**Модель/сервис:** ChatGPT / Claude / YandexGPT

**Входные данные:**

- Код функции/модуля
- Название функции и параметров

**Промпт:**

```
Ты — эксперт по документации Python-кода. Напиши документацию для следующей функции в формате Google/NumPy/Sphinx:

[код]

Требования к документации:
1. Описание назначения функции (кратко и ясно)
2. Описание всех параметров (имя, тип, описание)
3. Описание возвращаемого значения (тип, описание)
4. Пример использования (с результатом)
5. Возможные исключения (если есть)

Формат ответа: документация в стиле Google (или NumPy).
```

**Способ верификации:** проверить, что документация соответствует коду и синтаксису.

### 4. Генерация commit message

**Назначение:** автоматическое создание сообщения коммита по изменениям в коде (Conventional Commits).

**Модель/сервис:** ChatGPT / Claude / Ollama

**Входные данные:**

- `git diff --staged` (изменения, подготовленные к коммиту)

**Промпт:**

**text**

```
Ты — эксперт по Conventional Commits. Сгенерируй сообщение коммита для следующих изменений в коде:

[git diff]

Требования:
1. Следуй формату: <type>(<scope>): <subject>
2. Types: feat, fix, docs, style, refactor, test, chore
3. Subject — краткое описание на английском (не более 50 символов)
4. Body (опционально) — подробное описание (отвечает на вопросы: что и зачем?)
5. Footer — ссылка на задачу (Closes #TASK-123)

Формат ответа: только сообщение коммита.
```

**Способ верификации:** проверить соответствие Conventional Commits и содержание изменений.

### 5. Анализ требований и формализация

**Назначение:** помощь в формализации требований для проектной работы.

**Модель/сервис:** ChatGPT / Claude / YandexGPT

**Входные данные:**

- Описание задачи (на русском или английском)
- Целевая аудитория

**Промпт:**

**text**

```
Ты — бизнес-аналитик. Помоги формализовать требования к программному продукту.

Контекст:
[описание задачи и проблемной области]

Задание:
1. Сформулируй цель проекта (кратко)
2. Опиши контекст и проблемную область
3. Определи входы и выходы системы
4. Выдели пользовательские роли (actors)
5. Сформулируй функциональные требования (что система должна делать)
6. Сформулируй нефункциональные требования (производительность, безопасность)
7. Предложи критерии приёмки (как проверить, что требование выполнено)

Формат ответа: структурированный документ в Markdown.
```

**Способ верификации:** обсудить с командой и заказчиком (преподавателем).

### 6. Поиск ошибок в коде (Code Review)

**Назначение:** проверка кода на потенциальные ошибки, уязвимости и улучшения.

**Модель/сервис:** ChatGPT / Claude / GitHub Copilot

**Входные данные:**

- Код для проверки

**Промпт:**

```
Ты — эксперт по код-ревью Python-кода. Проверь следующий код и укажи все проблемы:

[код]

Проверь:
1. Синтаксические ошибки
2. Логические ошибки
3. Потенциальные уязвимости (SQL-инъекции, XSS)
4. Проблемы производительности (N+1 запросы, неэффективные алгоритмы)
5. Нарушения лучших практик (PEP8, аннотации типов)
6. Утечки памяти или ресурсов
7. Повторяющийся код (DRY)

Для каждой проблемы:
- Укажи строку кода
- Опиши проблему
- Предложи исправление

Формат ответа: список проблем с описанием и исправлениями.
```

**Способ верификации:** проверить каждое замечание вручную.

### 7. Объяснение кода

**Назначение:** объяснение сложного кода для обучения и документирования.

**Модель/сервис:** ChatGPT / Claude / DeepSeek

**Входные данные:**

- Код для объяснения
- Уровень детализации

**Промпт:**

```
Ты — опытный разработчик. Объясни следующий код так, чтобы его понял студент:

[код]

Объясни:
1. Что делает функция/модуль (назначение)
2. Как работает алгоритм (по шагам)
3. Какие структуры данных используются и почему
4. Какие есть потенциальные проблемы (производительность, сложность)
5. Как можно улучшить код

Формат ответа: пошаговое объяснение с примерами.
```

**Способ верификации:** проверить, что объяснение соответствует реальному коду.
